# Download receipt, publication and inverse approval

## Scoped two-stage boundary

`file_controller.download_file` now delegates to `ultron/core/downloads.py:request`, not a raw receive/write loop. Both the public helper and tool dispatcher use the same path. Structural URL and filename/path validation happen without DNS/network before first approval. Existing destination directory is mandatory, exact vacant target chosen once; no server Content-Disposition name override, extraction, execution, application opening or recursive parents.

1. **Fetch approval:** immutable exact canonical public URL (including path/query), target and immediate parent device/inode/mode. Callback consumes the one-shot grant and revalidates roots/vacancy/parent before network. Permission includes sending this request and network identity to the named server, not a promise of file safety. URL query secrets are exposed to the destination/approval surface; existing model/UI retention is unchanged.
2. **Save approval:** after bounded completed receipt, revalidate the original destination and request another immutable plan bound to exact bytes' SHA256, byte count, URL, target and parent. Bytes stay in memory in an immutable closure, not embedded as multi-megabyte plan JSON or written while awaiting approval. Deny/expiry/headless/unavailable second approval does not publish. Callback verifies kind/grant, path, size, hash, current root policy, parent and vacancy again before staging; no independent caller may invoke publication without the exact grant.

An existing source/network approval cannot be reused as save approval. The network worker's copied callback context is allowed only receipt, not publication. Public raw receive and private receive worker require the consumed fetch context. Direct publication requires its exact unconsumed save plan. These are application call-path safeguards, not a sandbox against arbitrary malicious Python/dependency replacement. Native/in-process trusted code still controls its own call graph.

## Transport changes and limits

Redirects are now **refused**, including same-origin/public-host redirects. This intentionally removes previous follow-up requests without exact destination approval. The adapter does not resolve/contact a Location target or return possibly credential-bearing Location details. Operators must obtain/approve the final public URL explicitly; the adapter doesn't discover it by following links. Other web research adapters retain their separate transport policies.

Original protections retained: HTTP(S) standard ports only, no URL userinfo/private/local literal targets; DNS requires every returned address public, numeric-IP connection with original HTTPS SNI/hostname certificate validation, no environment proxy inheritance, no native transport retries, response/pool closure, HTTP 200 only, no gzip/content-encoding expansion, reject ambiguous/malformed framing, 16MiB byte cap and 20-second caller receipt budget with bounded worker slots. Non-TLS HTTP remains supported with explicit in-transit modification warning. Server data is untrusted; a hash is identity, NOT malware scanning, content safety or trusted provenance.

Network context is copied only into the owned bounded receipt worker. Timed-out network work may finish after caller timeout but returns bytes only; it never gets publication code/target writes. No save prompt or file is produced from a late discarded worker result. DNS/OS/native blocking, queued work and socket behavior are not hard-killed. 20 seconds is a waiting-caller receipt budget, NOT a total approval-to-save deadline, process-tree kill guarantee or complete egress sandbox. Private/public resolution checks rely on current host resolver/network/CA trust and numeric-IP transport; global DNS/routing/egress isolation is not claimed.

## Publication and inverse

Save writes bytes to private same-directory `.ultron-download-*.part`, flushes/fsyncs, verifies its fingerprint/hash, revalidates target/parent, and hard-links it to the vacant target without overwrite. Published fingerprint must equal staged fingerprint before recording undo. Filesystems without required hard-link semantics fail; no unsafe fallback. Cleanup checks staging inode before unlink and refuses observed replacements. Successful publication with an ordinary cleanup failure reports an explicit WARNING and can leave duplicate private staging data. Uncertain failure never deletes the destination, retries or registers an unverified inverse. Existing tests exercise collisions, flush/link failures and cleanup warnings.

Successful saves register a private exact-entry session inverse, not `_undo_create`. Separate undo approval discloses full target/parent/fingerprint; inverse requires consumed session.undo context, current roots and unchanged file and parent, then removes only that unchanged file. Edited/replaced/same-bytes-new-inode targets and replaced parents refuse. Inverse does not remove staging copies or offer a native Trash recovery guarantee. Legacy `_undo_create` now fails closed, including direct helper calls; its former directory removal/raw unlink implementation is removed. Other registered callbacks retain their separately documented trust/precondition limits.

## Residual risk / compatibility

The original and destination content are not guaranteed safe: writing a filename under an allowed home path can indirectly trigger a watcher/application, even though this adapter never executes it. Root policy still defaults to home, not a dedicated download sandbox. Paths can be replaced after checks, during staging/publication and immediately before inverse unlink; parent identity isn't a complete immutable ancestor chain. Staging stat/unlink also races. No compare-and-swap, filesystem isolation, cross-process lock, global writer serialization, durable receipt/audit journal, crash reconciliation, secure erase, content encryption or shutdown admission barrier. File/native I/O can block beyond network budgets.

Second confirmation keeps up to 16MiB receipt bytes alive in memory until pending callbacks are released/expired/replaced and garbage-collected; no immediate secure erase or process-global multi-prompt memory budget is promised. A new prompt can supersede an earlier pending request under existing confirmation semantics. Denial after fetch doesn't revoke an already disclosed URL/network request. Existing UI/log/model retention is outside the adapter. Approval UI rendering of long/signed URLs still requires native validation. Old callers expecting synchronous save now receive pending confirmation; no successful download should be claimed from that state.

Coverage is scoped to this download wrapper and its receipt/publication/inverse helpers. Remaining Git/plugin/macro/inline effects, unrelated network/file writers, global permission graph, durable private audit and OS isolation remain open. Prior reports' legacy-download status is historical and superseded only for this path. Native/live provider/GUI certification is not implied.
