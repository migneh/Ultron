# File transfers and exact session undo: scoped migration

## Implemented boundary

Move/copy/rename public helpers and dispatcher reach `core.file_safety.transfer`, which only previews or requests host approval. The effect sink `_apply_transfer` consumes that exact single-use grant. Approval snapshots the canonical absolute source and final destination, copy/move intent, source identity/size/mtime/mode/SHA256 and source/destination parent device/inode/mode. Existing directory destinations expand to a child exactly once before approval; execution never retargets into a newly appeared directory. The original root predicate is re-evaluated at execution. Changed source/parent, revoked roots, destination conflict, unsupported types, symlinks/junctions or absent parents refuse. No recursive parent creation, directory transfer, clobber or cross-volume move fallback. Maximum file size remains 64 MiB; validation hashing reads local content before consent but does not send file contents to a provider.

Copy uses a mode-0600 private staging file in the destination directory, a no-follow/nonblocking source descriptor where supported, descriptor identity check, bounded streaming, fsync, source/content checks and atomic no-clobber hard-link publication. Published identity must match staging. Cleanup deliberately refuses an observed replacement staging inode. Move uses no-clobber hard-link publication, validates both paths then unlinks source; final destination identity checked before undo registration. This is NOT atomic rename/rollback. Failures after publication can leave both paths; uncertain failure no longer blindly unlinks destination. No retries. Unknown outcomes require checking the disclosed paths and `.ultron-copy-*.part` staging files; partial or unregistered successes may exist. Cleanup errors can leave private duplicate content.

Undo registration now occurs only inside a successful approved transfer. `transfer` retains its tuple shape but returns `(message_or_pending, None)` rather than exporting an effectful raw undo closure. High-level wrappers are asynchronous approval requests unless a test supplies a synchronous fake host callback. Existing callers were traced: file controller and former organization loop. The organization apply implementation has been removed; only bounded read-only preview remains. Alternate `actions/desktop.py` organize/clean implementations are also disabled, including direct helpers. No hidden category/archive directory creation or bulk moves. Wallpaper/list/stats remain unrelated paths.

## Session undo boundary

`core.undo.undo_last()` requests separate host approval for one immutable, randomly identified top-of-stack entry. Approval binds the ID, label and action-provided detail; transfer undo previews include full paths, expected destination fingerprint and parent identities. Headless/denied/expired previews preserve entries. On execution, the sink consumes approval and atomically checks the exact top object before popping it. Newly pushed/cleared/reordered stacks refuse; multiple simultaneous previews cannot invoke the same callback twice. Failed/partial callbacks remain consumed and are not retried. No raw callback is returned through the tool.

Transfer reversal checks roots, parent identities, exact unchanged destination fingerprint and vacant original path. Copy inverse removes only the unchanged copy; move inverse publishes a no-clobber hard link at the source, checks identities again, then removes destination. No destination overwrite. Native setting callbacks and older file callbacks remain trusted application code with their own weaker preconditions. The registry cannot prove that an arbitrary callback is a correct/safe inverse. It reports `Undo callback returned` and the actual callback result, not unconditional `Undone`. A callback may itself request another operation approval; the result is not interpreted as completed native reversal. Labels/details/history are session metadata, not durable audit. Main tool description and prompt now reflect approval and uncertain outcomes.

## Explicit limits / uncovered paths

This is not filesystem isolation: check-to-use races remain, especially path-parent replacement, source/destination replacement immediately before unlink, and staging stat/unlink. No descriptor-relative directory confinement or OS transaction. Paths, host runtime modules, callback code, user root policy and filesystem semantics are trusted; arbitrary malicious Python can bypass application conventions. Parent fingerprints bind immediate parents, not a complete persistent ancestor chain. Hardlinks and shared inodes can expose concurrent edits; no cross-process lock, ACL/ADS/xattr ownership preservation, encryption or secure erase. Hashing/copy/fsync have no hard wall-clock timeout; storage can block. No crash journal, durable undo, guaranteed persistence, shutdown admission closure, per-path transaction or process-tree sandbox. Concurrent distinct approved operations/undo callbacks may interleave; one shared file lock serializes these transfer/inverse code paths only. A late undo approval is rejected when session history was cleared; this is not a universal callback shutdown barrier.

**Create_file/create_folder, write/append/overwrite, delete/Trash and restore, download receive/publication, legacy `_undo_create`/`_undo_write`, unrelated plugin/macro/Git and other file producers are NOT sink-migrated by this batch.** They remain next P0 work. New generic undo approval reduces direct tool invocation risk but does not rewrite or certify those callbacks. Undo gallery/history can disclose action labels; logging outside the adapters is unchanged. Existing safe roots default to the entire home directory, not a dedicated sandbox, and no new narrower root provisioner is claimed. No native Trash/Windows/network/storage certification.

## Validation

30 new tests in `tests/test_file_transfer_consent.py` use temporary files/fake approvals only: headless/direct helper refusal, exact and separate inverse approvals, deny/expiry/replay, changed/replaced/deleted/symlink source, root revocation, occupied/retyped destination, one-time directory expansion, replaced parent, staged publication collision, uncertain unlink/cleanup failures, raw sink refusal, headless/denied/expired undo, changed/cleared stacks, sequential and parallel competing previews, actual inverse conflict after preview, full path/hash disclosure and disabled alternate bulk helpers. Prior transfer/download regression tests now explicitly fake host approval; obsolete organization apply tests now assert fail-closed behavior. Existing create/write tests still exercise unmigrated legacy paths, not evidence of permission coverage.

Full suite: **970 passed**, one existing Starlette warning. Targeted Ruff and diff checks clean. Tests do not touch real user files, native Trash, desktop settings or network. Global permission coverage remains partial. No commit/push; wake word `hey_jarvis` unchanged.
